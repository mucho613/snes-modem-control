# 65816のレジスタ幅とメモリアクセス規約

65816では、ステータスレジスタのM/XフラグによりAとX/Yの命令幅が実行時に変わります。
一方、ca65の`.a8`、`.a16`、`.i8`、`.i16`は機械語の即値サイズを決める宣言であり、
CPUのフラグを変更しません。この二つがずれると、即値の余分なバイトが次の命令として
実行されるなど、ソースから判別しにくい破損になります。

本リポジトリでは`cargo xtask asm-lint`がnormal、smoke、font-testの3プロファイルを
制御フロー解析し、ROM生成前にも同じ検査を必須で実行します。

## 通常プロシージャのABI

通常の`.proc`は、先頭にAとX/Yの入口幅を両方宣言します。

```asm
.proc example
  .a8
  .i16

  ; 本体
  rts
.endproc
```

`RTS`または`RTL`へ到達するすべての経路は、入口と同じ幅と、均衡したソフトウェア
スタックでなければなりません。別の通常プロシージャを`JSR`または`JSL`で呼ぶ箇所も、
呼出先の入口ABIと一致する必要があります。ローカルサブルーチンは呼出元ごとの
戻り先とスタック状態を分けて検査します。

## 幅の変更

生の`REP`、`SEP`、`XCE`、`PLP`と、プロシージャ途中の生の幅宣言は使用しません。
`src/macro/utility.asm`の次のマクロを使用します。

| 目的 | マクロ |
| --- | --- |
| Aだけ8/16-bitへ変更 | `m8` / `m16` |
| X/Yだけ8/16-bitへ変更 | `i8` / `i16` |
| AとX/Yを同時に8/16-bitへ変更 | `mi8` / `mi16` |
| `PHP`で保存した既知の幅を復元 | `plp_m8_i8`、`plp_m8_i16`、`plp_m16_i8`、`plp_m16_i16` |

分岐の合流地点で、機械語を生成せずに期待幅を宣言するときは
`assert_m8_i8`、`assert_m8_i16`、`assert_m16_i8`、`assert_m16_i16`を使います。
これは幅を変更する命令ではありません。リンターは全流入経路が宣言と一致することを
検査します。流入幅を実際に統一する場合は`m8`などを使います。

## Resetと割り込み

Reset入口はCPU仕様上A8/I8のエミュレーションモードです。`ResetFast`は
`enterNativeM8I16`を使い、ネイティブモードのA8/I16へ一度に移行します。

NMIは任意のA/I幅の命令間へ入るため、固定入口ABIを持ちません。割り込み
プロシージャは先頭に`interrupt_entry`を置きます。リンターはA8/I8、A8/I16、
A16/I8、A16/I16の4通りを個別に解析します。

`VBlankFast`は最初に`PHP`で元の幅を保存し、`mi16`の後にA/X/Yを固定サイズで
保存します。復帰側も`mi16`で固定サイズのまま取り出し、`plp_interrupt`で元の
動的な幅へ戻した直後に`RTI`します。`RTI`は`interrupt_entry`で宣言した
プロシージャだけで許可され、ソフトウェアスタックが空であることも検査されます。

## スタック検査

リンターは`PHA`/`PLA`、`PHX`/`PLX`、`PHY`/`PLY`、`PHP`/`PLP`、
`PHB`/`PLB`、`PHD`/`PLD`を幅込みで追跡します。`PEA`、`PEI`、`PER`が積む
生の16-bit値と、それを2回の`PLB`または16-bit `PLA`/`PLD`で消費する場合も
モデル化しています。

スタックに残りがある復帰、保存時と異なる幅での取り出し、ローカル
サブルーチン内だけで不均衡になる経路はエラーです。

## WRAMアクセス検査

数値サイズの`label: .res size`宣言はWRAM割り当てとして収集されます。A依存の
ロード、ストア、算術・比較命令と、X/Y依存のロード、ストア・比較命令について、
実行時幅と定数オフセットが割り当て末尾を越えないことを検査します。

例えばA16で`.res $1`を`LDA`したり、`.res $2`の`+ 1`へ`STA`したりすると
隣接変数まで読み書きするためエラーです。大きな領域の一部を狭い幅で触ることは
許可されます。添字アクセスの実行時境界はこの検査の対象外なので、各ループでも
上限を検証してください。

## QUsb2Snesの実行ペイロード

mailbox入力のWRAM書き込みに使う短い65816コードは、Rust側の型状態付き
`ExecutionPayload`で生成します。WRAM書き込みは、元のPとAを保存してA8へ
移行した状態でのみ追加でき、完成時にAとPを復元します。書込先は
`$7E0000..$7FFFFF`に限定し、FXPAK PROの256-byte実行領域も検査します。

## 実行方法

幅検査だけを短時間で実行する場合:

```powershell
cargo xtask asm-lint
```

監査表示だけ行い、違反があっても終了コードを失敗にしない場合:

```powershell
cargo xtask asm-lint --audit
```

通常の変更完了時:

```powershell
cargo xtask check
cargo xtask mesen-test
```

`rom`、`deploy`、`mesen-test`も内部で厳格な幅検査を先に実行します。新しい幅変更
マクロや終端マクロを追加した場合は、マクロ本体だけでなく
`xtask/src/asm_lint.rs`の転送モデルと単体テストも同じコミットで更新します。
